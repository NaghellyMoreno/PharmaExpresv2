# Contrato: F008 — El sitio publicado y la API responden solo por HTTPS y con las cabeceras HSTS, CSP y X-Content-Type-Options

- **Funcionalidad:** F008 en `feature_list.json` (prioridad 1, categoría `security`, `passes` no se toca)
- **Historias:** ninguna (funcionalidad transversal). Requisitos: RNF-012 (HTTPS y cabeceras) y RNF-026 (los estáticos de los paneles no contienen datos).
- **Fuente:** sección 3.13, punto 7 del contexto (versión 7); `docs/02-requisitos.md` (RNF-012, RNF-026); `docs/03-arquitectura.md` (tabla de seguridad, fila 7; tabla "Publicación"; trazabilidad de F008: "Todas (cabeceras); `vercel.json`; `GET /health`"); ADR 0002 (decisiones 1, 2, 4 y 5) y ADR 0016 (decisión 5); `contracts/F001.md` y `qa/F001.md` (helmet de la API); `contracts/F007.md` (tratamiento del paso manual que depende de la usuaria).

## Estado de partida (leído del repositorio, no es requisito)
**El código casi está completo. Falta verificarlo con pruebas y el paso 1 solo se puede comprobar en el despliegue real.**

Ya existe:
- API: `apps/api/src/app.ts` aplica `helmet` con CSP `default-src 'none'` y `frame-ancestors 'none'` (ADR 0016). Las pruebas existentes comprueban CSP y `nosniff` en varias respuestas. **Ninguna prueba comprueba `Strict-Transport-Security`**: es el hueco de la API (helmet lo emite por defecto, pero nadie lo verifica).
- Web: `apps/web/vercel.json` ya trae `headers` para `/(.*)` con HSTS, CSP, `Permissions-Policy`, `X-Content-Type-Options` y `Referrer-Policy`, con los valores que fija el ADR 0002 (decisión 4). Ninguna prueba lo verifica y nadie ha comprobado que la CSP no rompa la web actual.
- La reescritura `/api/:path*` de `vercel.json` tiene el destino `https://PHARMA_EXPRESS_API_DOMAIN/...`: es un marcador sin reemplazar (ver Pendientes de la usuaria).
- **Paneles:** hoy no existen paneles en el código. `apps/web/src` solo tiene `patient/` y `shared/` (pantallas P-01, rechazo, `/revocar` y P-02). Los paneles del dispensador y de administración son funcionalidades posteriores. Los paneles son rutas de la misma aplicación web y reciben las cabeceras por la regla `source: "/(.*)"`, que cubre cualquier ruta, así que no necesitan configuración propia (Confirmado por ADR 0002: la web "paciente y paneles" es un solo proyecto). Por eso, en F008 "cada panel" se verifica sobre las rutas que existan hoy y sobre la regla comodín; cuando se construya un panel, sus pruebas (o la regresión de este contrato) vuelven a correr (ver "Notas para funcionalidades futuras"). No se crean paneles ni rutas de paneles en F008.
- **`vercel.json` de la API:** el ADR 0002 decide que la API usa la detección sin configuración de NestJS y descarta un `vercel.json` personalizado en la API (alternativa "Un proyecto con `vercel.json` personalizado para ambos", que "pierde la detección"). Por tanto F008 **no crea** `apps/api/vercel.json`: las cabeceras de la API salen de `helmet`. La nota de `progress.md` ("faltan `vercel.json` de la API") queda sin efecto para F008. Si el developer encontrara que hace falta uno por otro motivo (por ejemplo cron, F049), se detiene y lo reporta al architect.

## Decisión sobre la CSP
- **Confirmado (ADR 0002, decisión 4):** valores de `apps/web/vercel.json`: `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; connect-src 'self' https://*.public.blob.vercel-storage.com; img-src 'self' data: blob:; media-src 'self' blob:; frame-ancestors 'none'; base-uri 'self'; form-action 'self'`. Se usan tal cual: no se inventan otros.
- **Inferido, para el developer:** `'wasm-unsafe-eval'`, el dominio de Blob, `media-src` y `blob:` pertenecen a funcionalidades futuras (lector de QR, subida de documentos, cámara). No se quitan: el ADR los fija. `style-src 'unsafe-inline'` lo fija el ADR; si la web actual no lo necesita, no se cambia sin architect (se anota como observación).
- **Regla:** el developer verifica la CSP contra la web actual (2.4). Si algo se rompe, aplica la política mínima que lo arregla (2.5), con el motivo, y avisa al architect para actualizar el ADR. No se relaja `script-src`.
- **Observación para el architect (no bloquea):** el ADR no fija el valor de HSTS de la API (helmet). El criterio 2.1 usa un umbral de 180 días (Inferido) y `vercel.json` de la web usa dos años con `includeSubDomains; preload`. Si la usuaria quiere unificarlos, lo decide ella.
